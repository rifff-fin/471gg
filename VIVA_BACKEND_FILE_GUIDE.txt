VIVA BACKEND FILE GUIDE — MEMBER 3

EASY RULE
1. Route file = API URL and allowed role.
2. Controller file = main logic.
3. Model file = MongoDB saved data.
4. Service/Middleware = external API or file helper.

MAYOR / COUNCILLOR OFFICIAL POSTS
First: routes/announcementRoutes.js
Say: This has announcement API routes and mayor/councillor access.
Then: controllers/announcementController.js
Say: This creates posts, checks jurisdiction, sends notifications, and manages posts.
Then: models/Announcement.js
Say: This saves author, jurisdiction, post type, images, comments and pinned comment.
Live updates: services/realtime.js

CLOUDINARY FIELD-WORK PHOTOS
First: routes/complaintRoutes.js
Find: POST /:id/reports and POST /:id/reports/:reportId/verify
Then: controllers/complaintController.js
Find: addCompletionReport and verifyCompletionReport
Say: These upload proof, notify officer, and let officer verify or return report.
Then: services/cloudinary.js
Say: This connects to Cloudinary and uploads optimized images.
Then: middleware/uploadMiddleware.js
Say: Images only and image-size limit.
Finally: models/Complaint.js
Find: beforeAfterReports
Say: This saves Cloudinary URLs, worker name, verification status and officer note.

OFFICER COMPLAINT DECISION
First: routes/complaintRoutes.js
Find: GET /officer/cases and POST /:id/review
Then: controllers/complaintController.js
Find: getOfficerComplaints and reviewComplaintByOfficer
Say: Officer chooses approve/reject/hold/resolve, writes signed note, citizen gets notice.
Then: models/Complaint.js
Find: officerNotes, assignedOfficer, publicLedger

GOVERNMENT SERVICE REQUEST SIGNING
First: routes/serviceRequestRoutes.js
Then: controllers/serviceRequestController.js
Find: updateServiceRequest
Then: models/ServiceRequest.js
Say: Officer/admin is required. The controller saves officer note, officer name, time and electronicSignature. The model stores status, reviewedBy, reviewedAt and signature.
