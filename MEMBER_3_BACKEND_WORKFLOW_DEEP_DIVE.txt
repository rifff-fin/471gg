MEMBER 3 — BACKEND WORKFLOW DEEP DIVE
Easy viva reference

REQUEST PATH: Frontend page -> API route -> protect login -> authorize role -> controller -> model/MongoDB -> notification/realtime -> JSON response.

FOLDER MEANING
routes/ = API URLs and allowed roles.
controllers/ = main business logic.
models/ = MongoDB data shapes.
middleware/ = login, roles and upload validation.
services/ = Cloudinary and Socket.IO helpers.
server.js = connects routes to /api URLs.

AUTHENTICATION
middleware/authMiddleware.js reads the Bearer JWT and puts the user on req.user. authorize("officer", "admin") blocks all other roles.
server.js registers /api/complaints, /api/announcements, /api/notifications and /api/service-requests.

1. MAYOR / COUNCILLOR POST FLOW
Frontend: frontend/src/pages/MayorDashboard.jsx monitors cases and manages posts.
Frontend: frontend/src/pages/OfficialUpdates.jsx is the public page and image composer.
Frontend: frontend/src/components/OfficialAnnouncementList.jsx displays cards and archive.
Frontend: frontend/src/pages/Feed.jsx sends pinnedForHours={24}.
Backend: routes/announcementRoutes.js defines URL and role protection.
Backend: controllers/announcementController.js checks jurisdiction, saves posts, sends citizen notifications, edits/deletes/pins posts and loads the dashboard.
Model: models/Announcement.js stores author, jurisdiction, type, complaint, images, comments, pinnedComment and editedAt.
Realtime: services/realtime.js sends live announcement events.
Create flow: POST /api/announcements -> role check -> jurisdiction check -> Cloudinary images -> MongoDB Announcement -> citizen notification -> live event.
Main routes: POST /api/announcements, GET /api/announcements/dashboard, PATCH /api/announcements/:id, DELETE /api/announcements/:id.
24-hour rule: Feed filters by createdAt for 24 hours; it does not delete old posts. The archive still shows them.

2. CLOUDINARY FIELD PHOTO FLOW
Frontend: frontend/src/pages/UploadCompletionReport.jsx lets worker select a real complaint and choose photos.
Frontend: frontend/src/pages/OfficerDashboard.jsx shows Before/After evidence and verification.
Frontend: frontend/src/pages/ComplaintDetail.jsx shows the same evidence on the complaint.
Backend: routes/complaintRoutes.js defines /:id/reports and verification routes.
Backend: controllers/complaintController.js contains addCompletionReport and verifyCompletionReport.
Service: services/cloudinary.js uses upload_stream and optimization.
Middleware: middleware/uploadMiddleware.js accepts images only and limits size.
Model: models/Complaint.js stores beforeAfterReports.
Upload flow: multipart request -> Multer validation -> Cloudinary secure_url/public_id -> Complaint saves URLs and worker note -> officer notification.
Verification route: POST /api/complaints/:id/reports/:reportId/verify. Verify resolves the complaint; return sends it back to In Progress.

3. OFFICER REVIEW AND SIGNING
Frontend: frontend/src/pages/OfficerDashboard.jsx provides queue, votes, comments, evidence, decisions and signed note.
Routes: routes/complaintRoutes.js contains GET /officer/cases and POST /:id/review.
Controller: controllers/complaintController.js contains getOfficerComplaints and reviewComplaintByOfficer.
Model: models/Complaint.js contains assignedOfficer, status, officerNotes, publicLedger, comments, upvotes and beforeAfterReports.
Decision flow: officer selects action and note -> role-protected review route -> controller changes status -> officer name/action/signature/ledger saved -> citizen notification.

EXACT GOVERNMENT SERVICE REQUEST API
Routes: routes/serviceRequestRoutes.js contains GET /api/service-requests/officer and PATCH /api/service-requests/:id.
Controller: controllers/serviceRequestController.js requires officer note and saves status, reviewedBy, reviewedAt and electronicSignature.
Model: models/ServiceRequest.js stores citizen, serviceType, status, officerComment, reviewedBy, reviewedAt and electronicSignature.

NOTIFICATION FLOW
models/Notification.js stores user, message, read state, complaint, announcement and serviceRequest links.
routes/notificationRoutes.js returns only the logged-in user's inbox.
frontend/src/pages/Notifications.jsx marks read and opens the linked page.
services/realtime.js sends notification:new to the user's Socket.IO room.

BEST SHORT VIVA ANSWER
"The route protects the endpoint and checks the role. The controller validates the request and performs business logic. The model saves audit data in MongoDB. Services handle Cloudinary or realtime notifications. The frontend displays the response and live update."

HONEST NOTE
The officer dashboard visibly handles complaints and field-work evidence. Government service-request approval/signing is protected and implemented in the backend API, but does not yet have a separate React officer screen.
